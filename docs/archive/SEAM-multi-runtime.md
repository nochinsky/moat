# The harness seam

Phase 4 of `docs/archive/PROGRAM.md` asks for the interface that `codexEntryScript` +
`parseCodexEvents` + the turn runner already implement to be written down, with **no behaviour
change**. This is that document.

It exists because moat owns a runtime it does not own: the agent is Codex's CLI, reached
through one pinned binary. Everything moat knows about that runtime has to pass through the
seam described here, and anything that does not is a place where a second runtime could not be
added without rewriting callers.

Nothing in this document is new. Every statement is a property the code has today, and the
line references are to the code as it stands.

---

## 1. Why there is a seam at all

moat drives the agent two ways:

| mode | what moat runs in the box | who sees the output |
| --- | --- | --- |
| a task (`moat run "<task>"`, `moat up "<task>"`) | `codex exec --json …` | moat parses it and prints rows, the answer and the cost |
| a session (`moat`, the TUI) | `codex …` on the inherited terminal | the user, directly |

Only the first has a machine-readable contract. The second is a pty and moat deliberately
parses nothing from it (SPEC §2.2b). The seam is therefore the **batch** seam: start the agent
in the box with a script, let it run to completion, read the stream it produced.

That is a deliberate simplification and it is the thing an ACP-style protocol would change.
It is named here so the difference is visible rather than implicit.

---

## 2. The interface

### 2.1 Host side

The seam has exactly one entry point in the product:

```
runCodexTask(paths: EnvPaths, body: string, opts: CodexRunOptions): Promise<number>
  cmd/main.ts
```

| element | meaning |
| --- | --- |
| `body` | a shell script, generated by `codexExecBody(prompt)` (`cmd/main.ts`). It is the *only* thing that knows the agent is Codex. |
| `opts.env` | the environment the box gets. Carries the provider configuration and the credential variable name, never the credential in a file. |
| `opts.egress`, `slirpBinary`, `egressRules` | which network the ephemeral boot gets. |
| `opts.timeoutSeconds` | seconds. Default 2700. One unit, everywhere. |
| returns | the agent process's exit code, unchanged. |

Its only dependency for running the box is `runInSandbox(paths, body, …)`
(`sandbox/launcher.ts`), which is runtime-agnostic: it takes a script and returns
`{ code, output, timedOut }`. **Nothing in `launcher.ts` knows what an agent is.**

### 2.2 Box side

The script's entire obligation is:

> write the agent's events to **stdout**, one JSON object per line; write human-facing noise to
> **stderr**; exit with the agent's status.

`codexExecBody` discharges it with `exec codex exec --json --skip-git-repo-check <prompt>
</dev/null`. The long-running box (`codexEntryScript`) has a different and much smaller
obligation — print a readiness line and outlive the credential — and produces no events at all.

### 2.3 The payload contract

`parseCodexEvents(text)` (`bundle/codex.ts`) turns the stream into:

```
CodexTurn = {
  tools:    { id, kind, detail, status: "started" | "completed", exitCode? }[]
  messages: string[]          // agent prose, in order
  usage:    { input, cached, output, reasoning } | null
  errors:   string[]          // real failures
  notices:  string[]          // advisories that are not failures
}
```

Three properties of this contract are load-bearing and are not incidental:

1. **Unknown event types are ignored, never guessed at.** A newer Codex must not make the
   parser invent rows.
2. **`usage.input` is the cache-*miss* count.** The wire's `input_tokens` *includes* the
   cached tokens, so the parser subtracts `cached_input_tokens` before anything prices it.
   Charging the raw field double-counted a mostly-cached turn by about ten times (measured;
   `docs/HISTORY.md`). Any new runtime must land in this same shape, or `lib/pricing.ts`
   silently prices the wrong number.
3. **A notice is not an error.** `isNotice` separates "Model metadata for X not found" from a
   real failure, so a cache miss does not read as a broken turn.

### 2.4 Who consumes the seam

| consumer | reads |
| --- | --- |
| `runCodexTask` | the whole `CodexTurn`: tool rows, messages, errors, notices |
| the cost footer | `usage` → `computeCost` (`lib/pricing.ts`) |
| `describeCodexTurn` | tool/error counts for the one-line summary |
| `moat run --json` | the whole `CodexTurn` plus `code`, `timedOut` |

## 3. What the seam is not

Naming the seam makes its edges visible, and these are the edges:

* **No streaming to the caller, on the task path.** `runInSandbox` *can* stream
  (`opts.onOutput` is how `moat verify` and the shell path print as they go), but
  `runCodexTask` does not pass it: the whole JSONL document is parsed once, after the
  process exits, and tool rows are printed then. Nothing is incremental about a turn.
* **No mid-turn interaction.** moat cannot answer the agent during a turn, because there is no
  channel to answer on. This is exactly what ACP would add.
* **No approval channel.** `approval_policy = "never"` is rendered into the config on every
  boot (`bundle/codex.ts`, `installCodexFiles`) so the question is never asked. moat's
  "never ask" stance is therefore a *configuration* fact, not a protocol one — nothing
  enforces it but the rendered file.
* **No session protocol.** A TUI session is a pty. There is no `session/new`, no resume, no
  listing.
* **No usage until the turn ends.** `turn.completed` is the only event carrying usage.

---

## 4. Invariants the seam must keep

Any second runtime behind this seam has to satisfy all of these, and they are the checklist
for the ACP spike in `docs/archive/PROGRESS.md`:

1. **No server, no port** (AGENTS.md invariant 6: the agent is a subprocess of the client, and
   nothing is proxied).
2. **The agent's output goes to stdout as data; the terminal is never driven by it** — every
   string from the box is stripped at the print boundary (`lib/terminal.ts`).
3. **The credential arrives as an environment variable and never as a file** (invariant 2).
4. **The agent gets no second sandbox** (invariant 3): moat's box is the boundary, and a
   weaker one next to it is worse than none.
5. **Whatever moat ships into the box is pinned by digest** (`lib/pins.ts`).

If you are here because you want to add a second runtime, read `RUNTIMES.md` first: it records
what that involves, why ACP is not the shortcut it looks like, and the token-accounting trap that
misprises a turn silently.

`bundle/codex.ts`, `bundle/codex-prompt.ts`, `bundle/model-catalog.ts` and
`bundle/instructions.ts` are **not** part of this seam. They render the files that make one
specific runtime behave, and a second runtime would have its own equivalents rather than a
generalisation of these.
