### Defects 1-9: verdicts and fixes

**1. `--verbose` is a no-op. REPRODUCED, FIXED.**
`lib/log.ts` read `process.env.MOAT_VERBOSE` at module load; `cmd/main.ts` set that variable
inside `main()` afterwards, so the module-level `verbose` constant was always its
pre-change value and all 13 `log.debug` sites were unreachable. Fixed by replacing the
constant with a mutable module field and adding `setVerbose()`, mirroring `setQuiet()`;
`main()` now calls it. The gate's end-to-end half (that `--verbose` actually prints) is
checked in `test/e2e-extras.sh`, section Z.

**2. `test/e2e-extras.sh` cannot fail. REPRODUCED.** 45 `FAILED` prints, no accumulator,
last statement `scrub_evidence`, so the exit status is always 0. `test/e2e-live.sh` has the
same shape. Fix follows the pattern `test/e2e-egress.sh:20,229` already uses. See "the gate"
below.

**3. `moat profiles --json`. REPRODUCED, FIXED.**
Measured before: it printed `{"base": [...]}` and *then* the human-readable text, because the
ternary that was meant to choose a shape was statically undefined and there was no `return`.
Now it emits the whole table (`base`, `profiles`, `full`, `baseProfileCount`) and returns.
Verified: `moat profiles --json | python3 -c ...` parses, lists all ten profile ids, and the
plain `moat profiles` output is unchanged.

**4. `moat status /nonexistent` leaks a raw ENOENT. REPRODUCED, FIXED.**
Measured before: `✗ ENOENT: no such file or directory, lstat '/nonexistent'` — an internal
error where the user's mistake was a path. `envPaths` resolves with `realpathSync`, which
throws; it now catches that and names the path and the two commands that help. Verified:
```
✗ no such directory: /nonexistent
  `moat up` creates an environment for the directory you run it in; `moat status --all` lists the ones that exist.
```
exit 1.

**5. `cmd/main.ts:1484` prints `left alone:` paths unstripped. REPRODUCED, FIXED.**
The paths come from the sandbox tree, and this was the one print site in `cmdApply` without
`stripAnsi`. Invariant 8 has no exceptions. Fixed.

**6. Catalog numbers interpolated unquoted into TOML. REPRODUCED, FIXED.**
Two halves, as reported: `lib/catalog.ts` copied `limit.context` / `limit.output` out of
fetched JSON with a bare cast, and `bundle/codex.ts` interpolated them into
`model_context_window` / `model_max_output_tokens` unquoted. A value JSON can hold but TOML
cannot read (`NaN`, `Infinity`, `1e999`, a string, a negative, a float) produced a config
Codex refuses to parse, naming a line the user never wrote. Both halves now validate:
`tokenCount()` in the catalog keeps only positive safe integers, and `tomlTokenCount()` in
the renderer drops an unusable count with a warning rather than writing it.
New coverage: `test/unit/catalog-parse.test.ts`,
`test/unit/codex-runtime.test.ts` ("a token count that is not a positive integer never
reaches the TOML bare"). Both were checked the way the program requires: reintroducing each
half of the bug makes the matching test fail.

**7. `sync/copyout.ts:411` uses `git branch --force`. REPRODUCED, FIXED.**
Confirmed by reading the code and by the shape of the fix: `git branch --force <name> <ref>`
and `git checkout -B <name> <ref>` both reset an existing branch in silence. This is the
command where the user decides what the agent's work becomes, so it must not discard work
that was already theirs. `applyBranch` now reads the local branch first (git has no
`--force-with-lease` for a local branch, so looking first is the only way) and refuses when
it exists and points somewhere other than the fetched ref, naming `--name` and
`git branch -D` as the ways through. A branch already at the fetched ref is not a conflict
and still needs no command at all.
Coverage: two tests in `test/unit/copyout-apply.test.ts`, checked by disabling the refusal
and watching them fail.
*Trap found while writing that test:* `refs/moat/agent` and `refs/heads/moat/agent` both
exist in that fixture, so the short name `moat/agent` is ambiguous — git warns and picks
one. The assertions read fully-qualified refnames. A test that reads the short name can pass
while looking at the wrong object.

**8. `test/evidence/onboard.txt` carries a plaintext session password. REPRODUCED, DELETED.**
It is tracked, it is from the deleted opencode runtime, and the password is right there in
the committed file (`password   <redacted-by-history-rewrite>`, from a server that no
longer exists). `test/evidence/audit.jsonl` is the same runtime's orphan. Both `git rm`'d.
Nothing referenced either file except the line in `docs/PROGRAM.md` that reports them; the
suite regenerates `onboard.txt` in section J when a key is present, and that regenerated file
is scrubbed like every other.
**This is a published secret and deleting the file is not enough** — the credential is in
this repository's history. Recorded below under "open items" as something the owner has to
decide about, because rewriting published history is not a decision this program can make
unilaterally.

**9. `docs/SPEC.md:805-809` duplicates the `exposure` bullet. REPRODUCED, FIXED.**
